# Critical User Flow 판별 기준

이 문서는 "이 플로우를 테스트 계획에 넣을까 말까"를 결정할 때 읽는다. 목표는 **개발자가 안심하고 리팩터링할 수 있는 최소한의 안전망**을 만드는 것이지, 모든 화면을 덮는 것이 아니다.

## 한 줄 기준

> 이 플로우가 조용히 깨졌을 때, 사용자나 사업에 **돌이키기 어려운 피해**가 생기는가?

"예"라면 CUF 후보다. "그냥 좀 불편한 정도"라면 후보에서 뺀다.

## 세 가지 렌즈 (하나라도 강하게 걸리면 CUF)

### 1. 매출(Revenue)

결제, 구독, 주문, 신청 "완료" 단계. 이 플로우가 막히면 돈이 안 들어오거나 사용자가 이탈한다.

- 예: 장바구니 → 결제 → 주문 완료, 대출 신청 → 제출, 요금제 업그레이드.
- 신호: "완료/제출/결제" 버튼이 끝에 있는 플로우, 전환 퍼널의 마지막 구간.

### 2. 데이터(Data integrity)

사용자가 입력한 값·거래 기록·상태가 **유실되거나 잘못 저장**되면 안 되는 플로우.

- 예: 폼 여러 단계 입력 → 저장, 금액·수량 계산, 주소/계좌 등록.
- 신호: 멀티스텝 폼, 금액/수치 계산 표시, "저장했는데 사라졌다"가 치명적인 화면.

### 3. 신뢰(Trust & safety)

본인확인, 인증, 권한, 금액·약관 표시처럼 **틀리면 신뢰가 무너지는** 플로우.

- 예: 휴대폰 인증·본인확인, 로그인/세션, 한도·금리 등 민감 수치 표시, 약관 동의 기록.
- 신호: 인증 단계, 법적/금융 표시, 보안·권한 분기.

## 우선순위 매기기

후보를 추렸으면 P0/P1/P2로 나눈다.

```
P0  세 렌즈 중 2개 이상 강하게 걸림 + 사용자 대다수가 지나가는 메인 경로
    → 반드시 테스트. (예: 결제 완료, 본인확인→결과 조회)
P1  렌즈 1개 강하게 걸림 또는 P0의 주요 분기/엣지
    → 테스트 권장. (예: 결제 실패·재시도, 신청 자격 미달 분기)
P2  걸리긴 하나 사용 빈도 낮음 / 우회 경로 존재
    → 여유 될 때. 계획서엔 적되 "후순위"로 명시.
```

빈도(얼마나 많은 사용자가 지나가나)와 심각도(깨지면 얼마나 아픈가)를 곱해서 본다. 둘 다 높으면 P0다.

## 흔한 안티패턴

### 과잉 선정 (모든 걸 CUF로)

화면마다 테스트를 깔면, 사소한 UI 변경에도 테스트가 무더기로 깨진다. 그러면 팀은 테스트를 신뢰하지 않고 꺼버린다. **테스트가 깨지는 게 목적이 아니라, 진짜 회귀를 잡는 게 목적**임을 기억한다.

빼야 할 것들:

- 정적 표시(소개 페이지, 배너 노출 여부, 푸터 링크).
- 스타일/레이아웃만의 문제(시각 회귀는 별도 도구 소관).
- 한 번 쓰고 마는 관리자 내부 화면(빈도 극히 낮음).

### 과소 선정 (메인 경로 누락)

반대로, "당연히 되겠지" 하고 결제 완료나 본인확인 같은 메인 경로를 빠뜨리는 실수. 사용자의 80%가 지나가는 경로는 거의 항상 P0다.

### "테스트하기 쉬운 것"에 끌리기

셀렉터 잡기 쉽고 인증 안 걸리는 화면이라서 고르는 건 함정이다. 선정 기준은 **난이도가 아니라 영향도**다. 인증이 걸려 어려운 플로우일수록 오히려 신뢰 렌즈에 강하게 걸리는 P0인 경우가 많다 — 어려움은 "선행조건/모킹 필요"로 계획서에 적고, 선정에서 빼지 않는다.

## 후보 → 계획 전환 체크

각 CUF 후보가 다음을 갖췄는지 확인한 뒤 계획서로 옮긴다.

```
[ ] 어떤 렌즈에 왜 걸리는지 한 줄 근거
[ ] 우선순위(P0/P1/P2)
[ ] 근거가 추측이 아니라 라우트/이슈/문서로 뒷받침됨
[ ] 시작 화면과 "완료" 정의가 분명함
```

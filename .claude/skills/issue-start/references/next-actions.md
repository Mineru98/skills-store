# 다음 행동

구현·증거 게시·코멘트까지 끝났으면 사람이 리포트를 검토하고 다음 행동을 고르게 한다.
1번 선택은 게시된 구현 결과에 대한 승인이다. 승인 전에는 `issue-end` 로 넘어가지 않는다.

## 선택지 (순서 고정)

AskUserQuestion 으로 제시한다. 마무리로 넘어가는 쪽이 기본값이다.

```text
질문   issue-start 13단계(다음 행동 선택)입니다. 다음으로 무엇을 할까요?

1. 검토 승인하고 PR 만들기 (권장) /issue-end — 게시된 증거를 확인하고 PR 까지 만듭니다
2. 이 이슈 더 손보기             계획에 남은 항목을 이어서 작업합니다
3. 다른 이슈 착수                /issue-start <번호>
4. 여기서 종료                   PR 은 나중에 만듭니다
```

선택지를 제시하기 전에 재료를 모아 함께 보여준다.

```bash
gh issue list --state open --limit 10 --json number,title,url,labels
git worktree list
```

상황에 따라 권장 위치를 바꾼다.

- `plan.md` 의 작업 계획에 **끝내지 못한 항목이 남아 있으면** 2번을 권장으로 올린다. 무엇이 남았는지 한 줄로 적는다.
- 검증 명령이 실패한 채로 왔으면 2번을 권장으로 올린다. **실패를 덮은 채 PR 로 넘기지 않는다.**
- 현재 이슈를 제외한 남은 열린 이슈가 하나도 없으면 3번(다른 이슈 착수)을 선택지에서 뺀다. 다른 이슈 착수는 남은 열린 이슈가 있을 때만 제안한다.
- 그 외에는 1번이 권장이다.

이슈·PR 은 `[설명](링크)` 형식으로, 워크트리 경로는 `WORKTREE_DISPLAY` 값으로 보여준다. 세부는 SKILL.md 의 `링크와 경로 쓰는 법`.

## 1번 — 검토 승인하고 PR

이 선택을 구현 결과에 대한 사람의 승인으로 기록하고 같은 워크트리에서 `issue-end` 로 넘긴다.
워크트리를 옮기지 않는다.

```text
/issue-end
```

넘길 때 아래를 함께 전달한다.

- 이슈 번호와 링크
- 방금 만든 커밋(구현 / 증거)
- 증거 파일 위치와 장수
- 이슈 코멘트 링크

`issue-end` 가 없으면 설치한다.

```bash
sh <migrate-skill-agent>/scripts/migrate-skill-agent.sh \
  --skill issue-end --target home --link --clone --flavor <claude|codex>
```

설치도 안 되면 **PR 을 대신 만들지 않는다.** 증거 재확인 없이 PR 을 여는 것이 이 스킬군이 막으려는 상황이다. 사용자에게 직접 `gh pr create` 를 실행하라고 안내하고, 증거 위치를 함께 준다.

## 2번 — 이 이슈 더 손보기

`plan.md` 의 남은 항목을 보여주고 무엇부터 할지 정한다. 작업이 끝나면 다시 이 4지선다로 돌아온다.

증거를 다시 찍어야 하면 **after 만** 다시 찍는다. before 는 이미 pure 상태에서 찍혔으므로 다시 찍을 수 없다.

## 3번 — 다른 이슈 착수

이슈 목록을 번호·제목·라벨로 보여주고 고르게 한 뒤 `/issue-start <번호>` 로 넘긴다.

현재 워크트리에서 그대로 시작하지 않는다. `issue-start` 가 새 워크트리를 만든다.

## 4번 — 종료

마무리 보고를 출력하고 끝낸다. 워크트리는 지우지 않는다.

```text
남은 일   PR 이 아직 없습니다 — 마무리하려면 /issue-end
```

## 하지 않는 것

- **PR 생성.** `issue-end` 의 몫이다.
- **merge.** `issue-merge` 의 몫이다.
- **워크트리·브랜치 삭제.** 증거 URL 이 브랜치에 의존할 수 있다. 정리는 `issue-merge` 가 통합을 마친 뒤에 한다.
- **사용자에게 묻지 않고 다음 스킬로 넘어가기.** 이 선택은 반드시 사용자가 한다.

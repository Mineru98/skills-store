# A. 테스트 독립성 — 깊은 판단

SKILL.md 1단계의 세부. 핵심 질문 하나로 요약된다: **이 테스트가 검증하려는 갈래는 어디서 시작하는가? 그 시작점까지는 어떻게 도달할 것인가?**

## 시작점 사고 (start-at-the-branch)

발표의 예시: 회원가입 플로우가 `약관동의 → 휴대폰인증 → 본인정보입력 → 결제수단등록 → 완료`라고 하자.
"결제수단등록 실패 시 에러 처리"를 검증하는 테스트가 약관동의부터 매번 클릭으로 다시 타야 할 이유는 없다.

- 검증할 갈래 = **결제수단등록 단계**.
- 그 시작점 = **약관동의·휴대폰인증·본인정보입력이 끝난 상태**.
- 따라서 그 끝난 상태를 *테스트용으로 미리 만들어 두고*, 결제수단등록부터 UI로 검증한다.

이렇게 하면 한 갈래의 결함이 다른 갈래 테스트를 오염시키지 않고, 실행시간도 갈래별 최소로 줄어든다.

## API 셋업 vs UI 검증 — 경계 긋기

"어디까지 API로 만들고, 어디부터 UI로 검증하나"가 핵심 결정이다.

원칙: **검증 대상이 아닌 모든 선행 단계는 API로, 검증 대상 갈래만 UI로.**

```
이 테스트가 검증하는 단계인가?
├── 아니오 (선행 조건일 뿐)  →  테스트 전용 셋업 API로 상태 생성
│                                예: POST /test/accounts {termsAgreed:true, phoneVerified:true}
└── 예 (이게 검증 갈래)        →  UI로 실제 사용자 동작을 수행하고 결과를 단언
```

경계가 애매하면 이렇게 자문한다:
- "이 단계가 깨지면, 이 테스트가 실패해야 하나?" → 예면 UI로 검증, 아니면 API로 셋업.
- "이 단계는 별도 테스트가 이미 검증하나?" → 그렇다면 여기서 또 UI로 탈 필요 없다.

## 테스트 전용 셋업 API가 없을 때

이상적으로는 백엔드가 테스트 전용 셋업 엔드포인트(시드 계정 발급, 상태 강제 전이)를 제공한다. 없다면 차선:

1. **인증/세션 상태 1회 생성 후 재사용.** 로그인을 한 번만 UI로 수행해 storage state를 저장하고, 이후 테스트는 그 상태를 로드해 시작한다. 메커니즘은 playwright-cli의 `.claude/skills/playwright-cli/references/storage-state.md`(state-save/state-load) 참조. 이 스킬은 "언제 그렇게 하나"를 결정하고, 문법은 그쪽을 따른다.
2. **글로벌 셋업으로 1회만.** Playwright `globalSetup`에서 인증/시드를 1회 수행하고 모든 테스트가 그 산출물(storage state 파일 등)을 공유한다. 단, 산출물은 읽기 전용으로만 쓰고 테스트가 변형하지 않게 한다.
3. **그래도 UI 선행이 불가피하면** 그 부분을 헬퍼 함수로 추출해 중복 코드만이라도 제거한다(실행시간은 줄지 않지만 유지보수성은 오른다). 이건 마지막 수단이다.

## 순서 의존·공유 상태 끊기

연쇄 실패의 흔한 원인:
- 테스트 A가 만든 레코드를 테스트 B가 조회 → A가 깨지면 B도 깨짐, 병렬 실행 시 비결정적.
- 모듈 스코프 변수에 상태 저장 → 테스트 간 누수.
- 같은 고정 계정/이메일을 여러 테스트가 동시에 변형.

고치기:
- 각 테스트는 자기 데이터를 자기가 만든다(고유 식별자: timestamp·uuid 접미사).
- 셋업은 `beforeEach`(테스트별 격리)에, 진짜 1회면 `beforeAll`/`globalSetup`에.
- Playwright는 기본적으로 파일 단위 병렬이다. 순서 가정이 깔려 있으면 병렬에서 깨진다 — 가정 자체를 없앤다.

## 판별 빠른 신호

다음이 보이면 독립성 작업이 필요하다:
- 여러 `.spec.ts`에 동일한 로그인/약관 클릭 시퀀스가 복붙돼 있음
- `test.describe.serial(...)`로 순서를 강제하고 있음(진짜 필요한 경우는 드물다)
- 한 `test()`가 화면 여러 개를 가로지르며 5단계 이상을 검증
- `beforeEach`에서 매번 로그인 폼을 `fill`/`click`

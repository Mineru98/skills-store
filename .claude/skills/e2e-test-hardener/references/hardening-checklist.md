# 머지 전 최종 점검표 + 보고 양식

SKILL.md 마무리 단계의 세부. 다듬은 테스트가 "견고해졌다"고 말하려면 아래를 통과해야 한다. 각 항목에 *왜*를 붙였다 — 기계적 체크가 아니라 판단을 위해서다.

## 점검표 (원칙별)

### A. 테스트 독립성
- [ ] **각 테스트가 검증 갈래의 시작점에서 출발한다.** 공통 앞부분(약관·인증·로그인)을 UI로 반복하지 않는다.
  - 왜: 반복은 실행시간을 누적시키고, 앞부분 결함이 모든 갈래를 연쇄로 빨갛게 만들어 진짜 원인을 묻는다.
- [ ] **선행 조건은 테스트용 API/셋업으로, 검증 갈래만 UI로.**
  - 왜: 테스트가 책임지는 범위가 명확해야 실패 신호가 정확하다.
- [ ] **테스트끼리 실행 순서·공유 상태에 의존하지 않는다.**
  - 왜: Playwright는 기본 병렬이라 순서 가정은 비결정적 실패를 만든다.

### B. 외부 의존성 모킹
- [ ] **통제 불가능한 외부 호출이 모두 모킹/고정됐다**(인증서·홈택스·전자증명서·외부앱·PG·외부 OAuth 등).
  - 왜: 외부를 그대로 때리면 느리고, 우리가 안 바꾼 외부 변경에 우리 테스트가 깨진다.
- [ ] **모킹 지점이 호출 위치에 맞다.** 클라이언트 호출은 `page.route`, 서버(SSR/BFF) 호출은 E2E 전용 환경변수.
  - 왜: 지점을 틀리면 모킹이 무시되고 테스트가 *조용히* 진짜 외부를 탄다. 가장 위험한 거짓 안전.
- [ ] **우리 비즈니스 로직은 모킹하지 않았다.**
  - 왜: 검증 대상을 모킹하면 테스트가 아무것도 보장하지 못한다.
- [ ] **모킹이 실제로 동작함을 확인했다**(외부로 나간 요청 없음 / 외부 다운에도 green).
  - 왜: "걸었다"가 아니라 "안 탔다"가 증거다.

### C. 플래키 예방
- [ ] **하드 대기 0건.** `waitForTimeout`/`sleep`/고정 지연이 없다. web-first 조건 대기로 대체.
  - 왜: 시간 베팅은 느린 CI에서 터지고 빠를 땐 낭비다.
- [ ] **셀렉터가 시멘틱하다.** role+name/label/text 우선, CSS 클래스·구조·nth-child 결합 없음(불가피하면 testid).
  - 왜: 구현 디테일에 결합하면 스타일/마크업 변경에 조용히 깨진다.
- [ ] **변경 테스트 번인 통과.** `--repeat-each`로 반복해 단 한 번도 실패하지 않았다.
  - 왜: 머지 후 추적보다 작성 직후가 압도적으로 싸다. "1번 실패"도 운영에선 빨개진다.

## 빠른 정적 스캔 (보조)

기계적으로 잡히는 것은 grep으로 먼저 걸러 시간을 아낀다. 단, 통과는 사람/실행 판단으로 확정한다.

```bash
# 하드 대기 잔존 검색 (변경 spec 범위)
grep -rnE "waitForTimeout|setTimeout\(|sleep\(" path/to/tests

# 취약 셀렉터 후보 (구조/클래스 결합)
grep -rnE "nth-child|locator\(['\"]\.|>\s*\w+\s*>" path/to/tests

# E2E 모킹 게이트가 운영에서 켜질 위험 (NEXT_PUBLIC 노출 금지)
grep -rnE "NEXT_PUBLIC_.*(E2E|MOCK)" src
```

scan은 거짓양성이 있다(주석 안의 단어 등). "발견 = 결함"이 아니라 "발견 = 확인 대상"이다.

## 사용자 보고 양식

다듬기가 끝나면 무엇을 왜 고쳤는지 원칙별로, 그리고 번인 결과를 간결히 보고한다. 예:

```
E2E 하드닝 완료 — checkout.spec.ts, payment-method.spec.ts

A 독립성
- 약관동의·휴대폰인증 UI 반복(3개 테스트) 제거 → 테스트용 셋업 API로 인증완료 계정 발급 후 결제 갈래부터 검증
- describe.serial 해제, 각 테스트가 고유 주문ID 생성하도록 격리

B 외부 모킹
- 결제 PG(클라이언트 호출) → page.route로 success/decline 2케이스 고정
- 인증서 검증(서버 SSR 호출) → E2E_MOCK_EXTERNAL 게이트로 고정 응답. 외부 미호출 확인

C 플래키
- waitForTimeout 4건 제거 → toBeVisible/waitForURL 조건 대기로 전환
- .btn-primary 등 클래스 셀렉터 6건 → getByRole(name) 시멘틱 전환
- 번인: --repeat-each=15 --workers=1, 두 spec 모두 15/15 통과 (실패 0)

남은 판단거리(있다면): ...
```

보고는 "다 고쳤다"가 아니라 **어떤 결정을 왜 했고 무엇으로 검증했는지**를 담아야 다음 사람이 신뢰한다.

# playwright-cli로 탐색해 플로우 단계 뽑기

이 단계의 목적은 **테스트를 만드는 게 아니라, 계획서에 적을 플로우 단계를 실제 화면으로 확인**하는 것이다. 브라우저로 둘러보며 "진입 → 입력 → 분기 → 완료"의 실제 화면 전환을 눈으로 보고 단계로 옮긴다.

> 브라우저 구동 방법(전체 명령·세션·옵션)은 여기서 다시 설명하지 않는다. 이미 있는 `playwright-cli` 스킬(`.claude/skills/playwright-cli/SKILL.md`)을 탐색 도구로 그대로 쓴다. 이 문서는 "탐색을 어떻게 계획으로 옮기나"만 다룬다.

## 탐색에 쓰는 최소 명령

```bash
playwright-cli open <url>     # 앱 진입 (필요 시 로그인 상태 등은 playwright-cli storage-state 참조)
playwright-cli snapshot       # 화면 구조·요소(ref) 확인 → 어떤 단계/입력이 있는지 파악
playwright-cli goto <url>     # 다음 화면으로 이동하며 플로우 따라가기
```

`snapshot` 출력의 요소 목록(버튼·입력·링크)은 "이 화면에서 사용자가 할 수 있는 행동"을 보여준다. 이걸 시나리오 단계로 옮긴다. 단, **셀렉터/ref(e3 등)는 계획서에 적지 않는다** — 계획은 "휴대폰 번호를 입력하고 인증 요청을 누른다" 수준이고, ref는 Author 단계에서 다시 잡는다.

## 탐색 → 계획 변환 패턴

화면 하나를 보면 다음을 메모한다:

```
화면: <URL 또는 화면 이름>
- 사용자가 할 수 있는 핵심 행동: <예: 약관 동의 체크, 다음 버튼>
- 이 화면의 "성공" 신호: <다음 화면으로 넘어감 / 특정 텍스트 노출>
- 다음 화면: <어디로 가는가>
- 막힌 지점: <인증/결제 벽 등>
```

이 메모들을 이으면 시나리오의 1·2·3·4 단계가 된다. test-plan-template.md의 "시나리오" 항목에 산문으로 옮긴다.

## 인증·결제 벽을 만나면 (중요)

탐색 중 로그인·휴대폰 인증·본인확인·결제처럼 **진짜로 진행하면 안 되는 단계**를 만나면:

1. 거기서 **멈춘다.** 화면에 보이는 자격증명·코드를 읽어 입력하지 않는다.
2. 그 지점을 계획서의 해당 CUF "선행조건"에 적는다. 예: "휴대폰 인증 단계 — 실제 SMS 발송 불가, 테스트 계정/모킹 필요".
3. 벽 너머의 단계는 기획서·이슈(discovery-sources.md)나 사용자 확인으로 보강하고, 모르면 오픈 질문으로 남긴다.

이렇게 하는 이유: 계획서는 "무엇을 테스트할지"를 정하는 문서지, 탐색 중에 실제 거래·인증을 발생시키는 자리가 아니다. 외부 의존을 어떻게 모킹/우회할지는 이후 Author/Hardener 단계가 결정한다.

## 어디까지 탐색하나 (멈추는 기준)

- CUF 후보의 시작 화면과 주요 단계 전환을 **확인할 수 있을 만큼만** 본다.
- 모든 분기를 클릭해볼 필요 없다. 계획에 적을 happy path와 "깨지면 아픈" 핵심 분기만 확인한다.
- 화면 구조가 명확해 단계를 충분히 적을 수 있으면 멈춘다. 탐색은 계획의 근거이지 그 자체가 목적이 아니다.

## 탐색이 불가능할 때

앱이 로컬에서 안 뜨거나 URL 접근이 막혀 있으면, 탐색 없이도 라우트 코드·기획서·이슈만으로 초안을 만든다(discovery-sources.md). 이 경우 계획서 각 시나리오의 "탐색 메모"에 "미탐색 — 라우트/기획 기반 추정"이라고 명시해 검토자가 신뢰 수준을 알 수 있게 한다.

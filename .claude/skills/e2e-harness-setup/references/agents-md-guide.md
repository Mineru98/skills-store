# AGENTS.md 작성 가이드

> 단계 1 의 깊이 문서. AGENTS.md 는 **코드베이스 지도**다. E2E 운영 규칙(SSOT)과 역할이 다르니 섞지 않는다.

## 목적

신규 입사자(=맥락 0 인 에이전트)가 "이 서비스가 뭐고, 어디에 뭐가 있고, 인증은 어떻게 도는가"를 5분 안에 파악하게 한다. 테스트를 짜려면 먼저 **대상의 경계와 핵심 플로우**를 알아야 한다.

## 채울 항목과 그라운딩 방법

근거 없는 일반론("이 앱은 사용자 경험을 중시합니다") 금지. 각 항목은 실제 파일을 읽고 채운다. 모르면 추정하지 말고 사람에게 묻거나 `TODO(확인필요)` 로 남긴다.

### 1. 무엇인가 / 누가 쓰나
- 한 문단. 도메인, 주 사용자, 비즈니스 목적.
- 그라운딩: `README`, `package.json` 의 description, 랜딩/온보딩 화면.

### 2. 아키텍처
- 앱·패키지 목록, 주요 디렉토리의 책임, 라우팅 방식.
- 그라운딩: 모노레포면 `apps/*`, `packages/*`, `turbo.json`/워크스페이스 설정. Next.js 면 `app/` 또는 `pages/` 구조, 미들웨어 위치.
- 이 저장소처럼 계층형 규칙이 있으면(`.claude/rules/**`) 그 계층(Pages→Presentation→Application→Infrastructure→Providers)을 한 줄 요약으로 인용한다.

### 3. 핵심 사용자 플로우 (E2E 가 지켜야 할 것)
- "로그인 → 대시보드 진입 → 핵심 액션 → 확인" 같은 **돈 되는 경로** 3~7개.
- 각 플로우는 진입 URL, 거치는 화면, 성공 신호(도착 URL/토스트/상태)를 적는다.
- 그라운딩: 라우트 정의, 주요 페이지 컴포넌트, 기존 E2E 가 있으면 그 `*.spec.ts` 제목.

### 4. 인증 & 접근제어  ← 테스트 하네스의 급소
여기가 부실하면 단계 3 fixture 가 통째로 틀어진다. 다음을 명시:
- **인증 방식**: 세션 쿠키 / JWT / OAuth / SSO 중 무엇인가.
- **세션 생성 방법**: 테스트가 세션을 어떻게 얻나. 로그인 폼 자동화인가, 아니면 `getServerState()`·테스트 전용 로그인 엔드포인트 같은 **서버 함수**인가. 서버 함수가 있으면 그 이름·위치·입력을 적는다.
- **역할/권한**: admin/user/guest 등 역할과 각 역할이 보는 화면 차이.
- **만료 동작**: 세션이 만료되면 무슨 일이 일어나나(리다이렉트, 특정 에러코드/종료코드). 이건 SSOT 의 "만료 신호"와 연결된다.
- 그라운딩: `middleware.ts`, `auth` 설정(next-auth 등), 로그인 API 핸들러, 세션 검증 유틸.

### 5. 로컬 실행 & 환경
- 개발 서버 명령과 포트, 그리고 **baseURL 이 무엇으로 결정되는가**(예: `E2E_BASE_URL` 환경변수, 없으면 `http://localhost:3000`).
- 필요한 환경변수 목록(비밀값은 키 이름만, 값 금지).
- 그라운딩: `package.json` scripts, `.env.example`, `playwright.config.*` 의 `use.baseURL`, 이 저장소의 `workflow-build.md` 규칙.

## 골격 템플릿

```markdown
# <서비스명>

## 무엇인가 / 누가 쓰나
<한 문단>

## 아키텍처
- 앱/패키지: ...
- 주요 경로: ...
- 계층 규칙: ...  (있으면)

## 핵심 사용자 플로우
1. <플로우명>: <진입 URL> → <화면들> → 성공 신호: <...>
2. ...

## 인증 & 접근제어
- 방식: <세션쿠키 | JWT | OAuth ...>
- 세션 생성: <getServerState() 위치/입력 | 로그인 폼 | 테스트 로그인 엔드포인트>
- 역할: <admin | user | ...> — 차이: ...
- 만료 동작: <리다이렉트/에러코드 ...>

## 로컬 실행 & 환경
- 개발 서버: `<명령>` (포트 <n>)
- baseURL 결정: <환경변수명> (기본값 <...>)
- 필요한 env: <KEY1, KEY2 ...>  (값 금지)
```

## 큰 Next.js 엔터프라이즈 저장소 팁

- 앱이 여러 개면 AGENTS.md 를 **루트 1개 + 앱별 1개**로 계층화한다. 루트는 지도, 앱별은 그 앱의 인증/플로우. (이 저장소의 `deepinit` 스킬이 계층형 AGENTS.md 생성을 도와준다.)
- 인증이 앱마다 다르면 "인증 & 접근제어"를 앱별로 분기해 적는다. 단일 서술로 뭉개면 fixture 가 한 앱에서만 동작한다.
- 이미 `CLAUDE.md`/`.claude/rules/**` 가 규칙을 갖고 있으면 **중복 서술하지 말고 링크**한다. AGENTS.md 는 규칙집이 아니라 지도다.

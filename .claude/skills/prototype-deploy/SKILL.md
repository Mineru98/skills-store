# Prototype Deploy

요구사항 → 클릭 가능한 정적 프로토타입 → tailnet HTTPS 링크.

결과물은 링크 하나다. 코드베이스의 실제 기능은 건드리지 않는다.

필요 도구: 로그인된 `tailscale` CLI, `python3`, `curl`, `lsof`.

## 1. 요구사항 정리

- 사용자가 준 요구사항을 항목별로 쪼갠다.
- 항목마다 "화면에서 무엇이 보이고, 사용자가 무엇을 하면, 어떻게 반응하는지"를 한 줄로 정한다.
- 해석이 갈려 결과가 달라지는 항목만 질문한다. 나머지는 가장 단순한 해석을 택하고 가정으로 기록한다.
- 현재 저장소에 실제 화면이 있으면 그 디자인 토큰·컴포넌트 모양·용어를 먼저 읽고 맞춘다.

## 2. 프로토타입 작성

위치는 `<저장소 루트>/.omc/artifacts/<slug>/`다. 저장소 밖이면 `~/prototypes/<slug>/`를 쓴다.

- 빌드 없는 정적 파일로 만든다. 진입점은 `index.html`이다.
- 외부 라이브러리는 버전을 고정한 CDN으로만 쓴다.
- 데이터는 그럴듯한 목업으로 하드코딩한다. 실제 API를 호출하지 않는다.
- 요구사항 항목마다 확인할 수 있는 화면·상태를 둔다. 상단에 항목 목록(번호 + 한 줄 설명)을 두고 각 항목 화면으로 이동하게 한다.
- 대안이 둘 이상이면 같은 페이지에서 A/B 토글로 비교하게 한다.
- 모바일 폭(390px)과 데스크톱 폭 모두에서 깨지지 않게 한다.

## 3. 로컬 확인

배포 전에 실제로 열어 본다.

- 브라우저 도구(ego-browser 등)가 있으면 `file://` 또는 로컬 서버로 열어 콘솔 에러 0건과 각 항목 화면 전환을 확인한다.
- 브라우저 도구가 없으면 최소한 HTML 구문과 참조 경로(스크립트·이미지)가 모두 존재하는지 확인한다.

## 4. 배포

```bash
bash <이 스킬 디렉터리>/scripts/deploy.sh <프로토타입 디렉터리> [port]
```

- 포트를 생략하면 19400–19499 중 비어 있는 포트를 고른다.
- 127.0.0.1에 `python3 -m http.server`를 띄우고 `tailscale serve --bg --https=<port>`로 연결한다. macOS Tailscale 앱은 디렉터리를 직접 서빙하지 못해서 이 방식을 쓴다.
- 스크립트는 tailnet URL이 200을 돌려줄 때만 성공한다. 실패하면 출력된 에러를 그대로 보고한다.
- 같은 프로토타입을 고쳐 다시 배포할 때는 파일만 수정한다. 서버가 디렉터리를 그대로 서빙하므로 재배포가 필요 없다.
- funnel(공개 인터넷)은 쓰지 않는다. 사용자가 명시적으로 요청할 때만 확인 후 쓴다.

내리기:

```bash
bash <이 스킬 디렉터리>/scripts/deploy.sh stop <port>
```

## 5. 전달

짧게 보고한다.

- 링크: 스크립트가 출력한 `url`
- 요구사항 항목별로 프로토타입에서 어떻게 표현했는지 한 줄씩
- 세운 가정과 남은 질문
- 로컬 경로와 내리는 명령(`deploy.sh stop <port>`)

tailnet 전용 링크라 같은 tailnet 기기에서만 열린다는 점을 함께 적는다. 로컬 서버는 재부팅하면 꺼지므로, 링크가 죽으면 같은 명령으로 다시 배포한다.

## 작업 요약

`issue-create`의 분해 기준을 문장 수·라벨 차이 중심에서 원자 후보 추출과 강결합 그룹 판정 방식으로 바꿨습니다.
같은 라벨의 독립 작업, API/UI 계약, 부분 결합, 공통 근본 원인, 5개 초과 요청을 구분합니다.

## 평가 데이터와 도구

- 서로 다른 요청 예시 500건: 개선용 400건 + 홀드아웃 100건
- 25개 산업, 4개 문체
- 단일 200건, 전체 분리 100건, 부분 결합 100건, 5개 초과 100건
- 요구사항 수 1·2·3·4·5·6개 이상 조합
- 생성 규칙, 스키마·중복·분포 validator, 모델 실행기, 오프라인 재채점기 추가

## 실제 모델 비교

최종 비교는 140회 실행했습니다. 튜닝과 홀드아웃의 baseline/current를 모두 `haiku`로 맞췄습니다. 홀드아웃 두 실행은 sample 40, repeat 1, concurrency 3, seed 33을 동일하게 쓰고 루브릭만 바꿨습니다.

- 튜닝 30건
  - 이슈 수 정확도: 86.7% → 93.3%
  - 그룹 완전일치: 83.3% → 90.0%
  - 쌍별 그룹 F1: 77.4% → 88.0%
  - 결정 정확도: 86.7% → 96.7%
- 홀드아웃 40건
  - 원자 요구 F1: 99.4% → 100.0%
  - 이슈 수 정확도: 80.0% → 97.5%
  - 그룹 완전일치: 77.5% → 97.5%
  - 쌍별 그룹 F1: 68.3% → 97.0%
  - 라벨 정확도: 98.4% → 100.0%
  - 결정 정확도: 82.5% → 97.5%
  - 과소·과대 분할: 12.5% / 7.5% → 0.0% / 2.5%
  - 5개 상한 처리: 100.0% → 100.0%
